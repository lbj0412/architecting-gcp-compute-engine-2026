SLIDE 06
글로벌 인프라 (Region, PoP, Network)
• 리전 (Region): 전 세계 40개 이상 (서울 asia-northeast3 포함)
• 영역 (Zone): 리전당 최소 3개 이상의 독립 고가용성 존
• 에지 접속 지점 (PoP): 지구를 둘러싼 Google 전용 고속 광케이블망
💬 강사 대본 (Instructor Script)
"화면에 보이는 지도가 바로 Google Cloud의 글로벌 인프라 지도입니다. 파란선은 지구 전체를 감싸고 있는 구글 전용 사설 해저 광케이블망입니다. 우리가 사용하는 서울 리전(`asia-northeast3`)을 비롯해 전 세계 40개 이상의 리전이 존재하며, 각 리전은 최소 3개의 독립된 존(Zone)으로 구성되어 완벽한 장애 격리와 고가용성(HA)을 제공합니다."

SLIDE 08
일반적인 문제에 대한 솔루션 다양성
• 💡 하나의 과제에 대해 2개 이상의 솔루션 제공
• 가상 머신(IaaS), 컨테이너(CaaS), 서버리스(PaaS) 등 다중 선택지 제공
💬 강사 대본 (Instructor Script)
"Google Cloud 아키텍팅의 핵심 원칙 중 하나는 '하나의 문제에 항상 2개 이상의 솔루션이 존재한다'는 점입니다. 예를 들어 웹 서버 하나를 띄우더라도 Compute Engine VM으로 올릴 수도 있고, GKE 컨테이너로 띄우거나, Cloud Run 서버리스로 배포할 수도 있습니다. 조직의 엔지니어링 역량과 비용에 맞춰 최적의 옵션을 선택할 수 있습니다."
SLIDE 09
솔루션 연속성 (Solution Continuum)
• IaaS (Compute Engine): SysOps 직접 관리, OS 제어
• CaaS (GKE): DevOps 클러스터 및 Pod 관리
• PaaS / Serverless (Cloud Run): No-Ops 완전 관리형
💬 강사 대본 (Instructor Script)
"이 표는 IaaS부터 SaaS까지의 솔루션 연속성을 나타냅니다. 왼쪽 IaaS로 갈수록 OS와 커널까지 내 마음대로 제어할 수 있지만 직접 관리해야 하는 운영 부담(SysOps)이 커집니다. 반대로 오른쪽 서버리스(Cloud Run)로 갈수록 구글이 인프라를 100% 관리해주므로 인프라 관리 부담이 전혀 없는 노옵스(No-Ops) 환경을 누릴 수 있습니다."
SLIDE 10
인프라, 사용자, 애플리케이션 구조
• 기반 인프라 (Underlying Infrastructure): 구글 글로벌 사설망, VM, VPC
• 애플리케이션 계층: GKE Pod, Cloud Run, 서버리스 함수
• 사용자 & 디바이스: IAM 인증, IAP, 보안 게이트웨이
💬 강사 대본 (Instructor Script)
"클라우드 아키텍처를 도시 구조에 비유해 보겠습니다. 하부의 도로와 지하철, 전력망 같은 도시 인프라가 바로 구글의 '기반 인프라(Underlying Infrastructure)'입니다. 그 위에서 달리는 차량이나 상점이 '애플리케이션'이며, 도시에 거주하는 시민이 바로 '사용자'입니다. 우리는 이번 과정에서 가장 밑바탕이 되는 인프라 레이어를 집중적으로 배우게 됩니다."
SLIDE 11
컴퓨팅 서비스 01: Compute Engine
• 대표 IaaS (Virtual Machines)
• 커스텀 CPU/RAM 사양, Live Migration (무중단 마이그레이션), GPU/Spot VM
💬 강사 대본 (Instructor Script)
"첫 번째 주요 서비스는 바로 이번 교육 과정의 주인공인 **Compute Engine**입니다. 클라우드 상에서 가상 머신(VM)을 필요에 따라 생성하는 IaaS 서비스입니다. 구글만의 차별점인 'Live Migration' 기능 덕분에 물리 서버 하드웨어 점검 중에도 수강생분의 VM이 꺼지지 않고 다른 물리 서버로 무중단 이동됩니다."
SLIDE 12
컴퓨팅 서비스 02: Google Kubernetes Engine (GKE)
• 관리형 CaaS (Container-as-a-Service)
• GKE Standard (노드 제어) & GKE Autopilot (완전 관리형 K8s Pod 운영)
💬 강사 대본 (Instructor Script)
"두 번째는 **GKE(Google Kubernetes Engine)**입니다. 쿠버네티스를 최초로 만든 구글의 기술력이 집약된 대표 관리형 컨테이너 서비스입니다. 특히 최신 GKE Autopilot 모드를 사용하면 노드 서버 관리조차 신경 쓸 필요 없이 컨테이너 **Pod** 단위로만 깔끔하게 배포하고 운영할 수 있습니다."
SLIDE 13
컴퓨팅 서비스 03: App Engine
• 전통적 PaaS (Platform-as-a-Service)
• Standard & Flexible 환경, 서버 프로비저닝 없이 코드 즉시 배포
💬 강사 대본 (Instructor Script)
"세 번째는 Google Cloud의 오리지널 PaaS인 **App Engine**입니다. 개발자가 서버 구축이나 OS 패치 걱정 없이 오직 작성한 소스 코드만 제출하면 구글이 런타임 환경을 자동으로 구성하고 트래픽 확장을 알아서 처리해 주는 완벽한 코드 중심 서비스입니다."
SLIDE 14
컴퓨팅 서비스 04: Cloud Functions
• 이벤트 기반 FaaS (Function-as-a-Service)
• Cloud Storage 파일 업로드 / Pub/Sub 수신 반응 실행, 2세대 Cloud Run 기반
💬 강사 대본 (Instructor Script)
"네 번째는 이벤트 기반의 서버리스 함수인 **Cloud Functions(Cloud Run Functions)**입니다. 스토리지에 사진이 업로드되거나 큐 메시지가 도착할 때 1초만 짠 하고 실행되는 단일 기능 스크립트에 적합합니다. 요청이 없을 때는 요금이 0원이며, 2세대는 Cloud Run 인프라 위에서 구동되어 성능이 대폭 향상되었습니다."
SLIDE 15
컴퓨팅 서비스 05: Cloud Run
• 모던 서버리스 컨테이너 플랫폼
• 표준 Docker 이미지 기반, 0부터 수천 개까지 초단위 자동 스케일링
💬 강사 대본 (Instructor Script)
"다섯 번째는 현시점 구글 클라우드에서 가장 매력적인 서버리스 플랫폼인 **Cloud Run**입니다. Docker 컨테이너 이미지 하나만 만들어 던져주면, 트래픽이 없을 땐 인스턴스 0개로 줄어들어 요금이 안 나가고, 요청이 몰리면 1초 만에 수백 개로 자동 확장됩니다. 언어나 라이브러리 제약이 전혀 없습니다."

SLIDE 23
실습 비용 및 리소스 관리 수칙 (FinOps Guide)
• ⚠️ 수업 종료 및 미진행 시 VM OFF 필수
• 💰 GCP 결제 집계는 최소 2일(48시간) 후 반영되므로 사전 비용 고려 필수
💬 강사 대본 (Instructor Script)
"다음은 비용 관리 수칙입니다. **수업이 종료되거나 실습을 쉬는 시간에는 반드시 켜둔 Compute Engine VM을 OFF(중지) 상태로 바꾸셔야 합니다.** 또한 GCP의 요금 통계 집계는 최소 48시간(2일) 뒤에나 시스템에 반영되기 때문에 '지금 요금 안 찍혔네?' 하고 방치하시면 2일 뒤 큰 금액이 청구됩니다. 항상 비용을 염두에 두고 자원을 아껴주세요."
💡 퇴실 점검 수칙: 매일 수업 마감 10분 전 수강생들에게 VM 인스턴스 전원 중단을 일괄 안내하세요.
